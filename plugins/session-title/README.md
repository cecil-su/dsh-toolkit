# 会话标题（session-title）

`@local/session-title` 根据 DSH 新会话的首条用户消息生成 `MMDD｜类型｜主题` 短标题，例如 `1123｜探索｜Codex 登录`。日期取会话创建时间（Asia/Shanghai）；已有标题不会因为包改名而批量刷新。

| 首条消息 | 标题来源 |
| --- | --- |
| 普通问题，或仅提到任务（例如 `看看 #128`） | 可用时将首条消息的节选发给所选模型，提取「对象＋动作」；无合适模型结果时用本地规则。普通主题目标 6–10 字，最多 14 个字符（含英文和空格）。 |
| Windows 上的 `开启 #128`、`执行任务 #128`、`继续 #128` 等任务指令 | 用本机 `taskctl.exe` 执行 `task context <编号> --require-read-only`。命中即沿用 Agent Steward 原题；未命中、查询失败或不支持只读参数时，仍按普通会话命名。 |

任务原题和手动标题不受普通主题长度限制。插件不把查询到的任务正文交给模型，不领取、执行或关闭任务，不关联 Herdr 会话。

## 手动标题与历史兼容

- 在 DSH 手动重命名（例如把常驻入口命名为 `## TASK`）会固定标题，并取消在途的自动命名。后续对话不会覆盖它；只有显式重新生成标题才解除固定。
- 新包继续使用旧的内部标题 provider ID `steward-session-title-compact`。DSH 的自动标题及标题模型请求会记录来源；保留此标识让新旧记录指向同一提供器。它不是包名或 Loader 行 ID，不需要改写历史日志。已有会话及其分叉不会被批量重命名。

## 从旧包切换

1. 在 DSH 的插件管理中先卸载或停用**整个旧包** `@local/steward-session-title`，不要同时启用新旧包：DSH 只允许一个自动标题提供器。
2. 从本目录安装 `@local/session-title`。新包添加的 Loader 行 ID 为 `local-session-title`；`session-title` 已由 DSH 内置标题服务占用，所以不使用该行 ID。与旧版一样，本包只禁用内置的 `session-title-llm` 生成器，不禁用标题服务。
3. 启用范围是当前 DSH profile，而非单个工作区。要恢复内置策略，请停用或移除**整个新包**，不要只关闭插入的行；已有标题不会随卸载回滚。
